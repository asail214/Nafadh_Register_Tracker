== المتطلبات الأساسية (مختصر) ==
- عام بلا تسجيل دخول: 3 مسارات (تحديث الحالة / مشكلة / اقتراح). اسم + بريد إلزاميان، البريد يُطبّع.
- مشكلة: تصنيف، عنوان، وصف، هل تمنع الإكمال، 1–3 صور JPG/PNG/WebP بمعاينة وضغط في المتصفح.
- اقتراح: عنوان، وصف، 1–3 صور اختيارية.
- نجاح + «إرسال مشاركة أخرى». توضيح أن الهوية إفادة ذاتية.
- /admin: Supabase Auth + جدول admins يُتحقق منه في DB (RLS). إحصاءات، قائمة مستهدفين + استيراد CSV،
  إضافة يدوية، تأكيد يدوي، تاريخ الحالات، بلاغات بفلترة وتغيير حالة (جديد/قيد المراجعة/تم الحل)،
  تصدير CSV بـ UTF-8 BOM، QR فقط عند وجود VITE_PUBLIC_URL حقيقي.

== القرارات ==
- React + TS + Vite، بلا react-router (توجيه بسيط بالمسار: / و /admin) + إعادة كتابة SPA لـ Vercel/Netlify.
- الشعار: logo-blue.png (شعار نفاذ) منسوخ إلى public/nafadh-logo.png. شعار الهيئة غير مستخدم.
- الكتابة العامة عبر RPC (SECURITY DEFINER) واحدة submit_entry تتحقق من المدخلات + حد معدل لكل بريد.
- الصور: bucket خاص "attachments"؛ الزائر INSERT فقط (لا قراءة)، حد 1MB وأنواع صور فقط؛ الإدارة روابط موقّتة.
  لا حاجة لـ Edge Function في هذه المرحلة.
- الإحصاءات تُحسب في الواجهة من بيانات الإدارة (عشرات السجلات) بدالة نقية مُختبرة.
- Demo: عند غياب VITE_SUPABASE_URL/ANON_KEY، تخزين محلي في المتصفح فقط مع شارة واضحة.
- الاستضافة: Vercel Hobby للاستخدام الشخصي غير التجاري فقط → يُشرح القيد؛ بديل Netlify Free أو استضافة مصرح بها.
