# متابعة مستقلي نفاذ للعمل الحر (NAFADH Freelancers Tracker)

موقع متابعة تجريبي مستقل (ليس منصة نفاذ ولا يرتبط بها تقنيًا) لجمع حالة تسجيل المستقلين واكتمال ملفاتهم (إفادة ذاتية)، واستقبال المشكلات والاقتراحات، مع لوحة إدارة في `/admin`.

## التشغيل المحلي

```bash
npm install
npm run dev        # http://localhost:5173  ولوحة الإدارة: http://localhost:5173/admin
npm test           # اختبارات الواجهة + اختبارات schema.sql على PGlite
npm run build      # الناتج في dist/
```

بدون ملف `.env.local` يعمل التطبيق في **وضع تجريبي**: البيانات تُحفظ في المتصفح فقط وتظهر شارة «بيانات تجريبية لا تُحفظ سحابيًا»، ولوحة الإدارة تُفتح دون دخول (لأنها لا تحتوي إلا بيانات هذا المتصفح).

## الربط مع Supabase (الخطة المجانية)

1. أنشئ مشروعًا على supabase.com بالخطة **Free** (لا تُدخل بطاقة دفع ولا تفعّل أي ترقية).
2. **SQL Editor** ← الصق محتوى `supabase/schema.sql` كاملًا ← Run. (الملف آمن لإعادة التشغيل.)
3. **Authentication ← Sign In / Providers**: أوقف «Allow new users to sign up» حتى لا يُنشئ أحد حسابًا بنفسه.
4. **Authentication ← Users ← Add user**: أنشئ حساب الإدارة (بريد + كلمة مرور قوية)، وانسخ `User UID`.
5. في SQL Editor امنحه الصلاحية:
   ```sql
   insert into public.admins (user_id) values ('<USER_UID>');
   ```
6. **Project Settings ← API**: انسخ `Project URL` و `anon public key` إلى ملف `.env.local` (انظر `.env.example`):
   ```
   VITE_SUPABASE_URL=...
   VITE_SUPABASE_ANON_KEY=...
   ```
   مفتاح anon عام بطبيعته ومحمي بسياسات RLS. **لا تضع `service_role` في أي متغير `VITE_` أو في الواجهة.**
7. `npm run dev` ثم جرّب الإرسال وادخل `/admin`.
8. **SQL Editor**: نفّذ `supabase/002_visits_notifications.sql` (إضافي فقط، لا يحذف أو يغيّر بيانات، آمن لإعادة التشغيل).
   يضيف: جدول الزيارات `visits` + الدالتين `record_visit` و `visit_stats`، عمود `seen_at` للإشعارات، وتفعيل Realtime
   للجدولين `status_updates` و `tickets`.

### متغيرات Vercel مقابل التطبيق
التطبيق يقرأ `VITE_SUPABASE_URL` و `VITE_SUPABASE_ANON_KEY` فقط (Vite لا يكشف إلا المتغيرات التي تبدأ بـ `VITE_`).
تكامل Supabase في Vercel يضيف `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` وغيرها؛ انسخ قيمتي هذين
المتغيرين إلى `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` ثم Redeploy. لا تنسخ `SUPABASE_SERVICE_ROLE_KEY` أو
`SUPABASE_JWT_SECRET` أو `POSTGRES_*` إلى أي متغير `VITE_`.

### الزيارات والإشعارات والتصدير
- **الزيارات:** زيارة واحدة لكل جلسة متصفح على الصفحة العامة فقط (لا `/admin`)، بمعرّف عشوائي محفوظ في المتصفح، بلا IP.
  الخادم يتجاهل المعرّف نفسه خلال 30 دقيقة ويضع سقفًا 600 زيارة/ساعة. نسبة التحويل = المشاركون الفريدون (بالبريد) منذ
  أول زيارة مسجّلة ÷ الزوار الفريدون × 100 — تقريبية.
- **الإشعارات:** عدّاد «غير مراجَعة» في لوحة الإدارة + Supabase Realtime (يصل فقط لمن تسمح له RLS بالقراءة = الإدارة)
  مع تحديث احتياطي كل 60 ثانية. تصور Telegram في `docs/TELEGRAM_PLAN.md` (غير مُفعّل).
- **Excel:** زر «تصدير Excel» ينشئ `.xlsx` بأربع أوراق RTL بخط Cairo. المكتبة (exceljs) تُحمَّل عند الضغط فقط.

### نموذج الأمان (ملخص)
- كل الجداول عليها RLS؛ القراءة والتعديل للإدارة فقط عبر `is_admin()` (جدول `admins`) — التحقق في قاعدة البيانات لا في الواجهة.
- الزائر لا يملك أي صلاحية على الجداول؛ الإرسال الوحيد عبر الدالة `submit_entry()` التي تتحقق من المدخلات، وتحدّ المعدل (10 مشاركات/بريد/ساعة و120 مشاركة/10 دقائق إجمالًا).
- الإدارة تستطيع تغيير **حالة** البلاغ فقط، لا محتواه.
- الصور في bucket خاص `attachments` (غير عام، 1MB، صور فقط). الزائر يرفع فقط ولا يقرأ؛ الإدارة تفتحها بروابط موقّتة (10 دقائق). تُضغط الصور في المتصفح (≤900KB) وتُزال بيانات EXIF.
- حدود معروفة (نموذج تجريبي): يمكن نظريًا رفع صور دون إكمال الإرسال (ملفات يتيمة ≤1MB)؛ لا يوجد CAPTCHA؛ البريد إفادة ذاتية لا يُتحقق من ملكيته. لا تعتبر هذه الحماية إنتاجية كاملة.

### استيراد القائمة المرجعية
ملف CSV فيه عمود للاسم وعمود للبريد (عناوين مثل `name,email` أو `الاسم,البريد`، أو بلا عناوين). يُطبَّع البريد وتُحذف التكرارات.

## النشر (لا يتم إلا بعد موافقة صريحة)

الموقع ثابت (static) ويُبنى بـ `npm run build` إلى `dist/`. ملفات إعادة توجيه SPA جاهزة: `vercel.json` و `public/_redirects`.

- **تنبيه Vercel Hobby:** شروط الخطة المجانية تسمح بالاستخدام **الشخصي غير التجاري** فقط. هذا المشروع مرتبط بعمل جهة حكومية، وكونه «غير معتمد رسميًا» لا يجعله مشروعًا شخصيًا تلقائيًا؛ لذا يُنصح بالتحقق من الشروط أو اختيار بديل.
- **بدائل دون تغيير الكود:** Netlify (الخطة المجانية) — Build command: `npm run build`، Publish directory: `dist`؛ أو أي استضافة ثابتة مصرّح بها من الجهة.
- أضف متغيرات `VITE_SUPABASE_URL` و `VITE_SUPABASE_ANON_KEY` في إعدادات الاستضافة، وبعد معرفة الرابط النهائي أضف `VITE_PUBLIC_URL` لتفعيل زر تنزيل QR، ثم أعد البناء.
- أضف رابط الموقع في Supabase: **Authentication ← URL Configuration ← Site URL**.

## الخصوصية
لا تُجمع كلمات مرور نفاذ أو رموز تحقق أو مستندات. لا تُدخل بيانات حقيقية قبل اعتماد مكان الاستضافة والتخزين. ملفات CSV المصدّرة تحتوي بيانات شخصية.
